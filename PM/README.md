# Project Management Course

> A practical and structured Project Management course covering the complete project lifecycle: **initiation → planning → execution → monitoring & control → closure**.

This repository is a complete learning guide for understanding how projects are defined, planned, executed, controlled, and delivered.

The goal is not only to learn Project Management terminology, but to develop the ability to **think like a Project Manager**: define outcomes, manage constraints, coordinate people, identify risks, make decisions, communicate clearly, and deliver measurable value.

# 1. Course Overview

Project Management is the discipline of organizing people, resources, time, money, and activities to achieve a defined project objective.

A project manager continuously answers:

* What are we trying to achieve?
* Why are we doing it?
* What exactly is included?
* Who is responsible?
* When must it be completed?
* How much will it cost?
* What could go wrong?
* How will we measure success?
* How will changes be handled?
* How will stakeholders be informed?

The central idea is:

> **A project is successful when it delivers the intended value within an acceptable combination of scope, time, cost, quality, risk, and stakeholder expectations.**

---

# 2. What Is a Project?

A **project** is a temporary effort undertaken to create a unique product, service, or result.

A project normally has:

* a defined objective
* a beginning
* an end
* limited resources
* stakeholders
* uncertainty
* deliverables
* constraints

### Examples

* Building a mobile application
* Developing an AI model
* Implementing an ERP system
* Constructing a warehouse
* Launching a new product
* Migrating a database
* Establishing a manufacturing line
* Implementing a supply-chain optimization system

---

# 3. Project vs Operations

| Project               | Operations                   |
| --------------------- | ---------------------------- |
| Temporary             | Continuous                   |
| Unique outcome        | Repetitive activities        |
| Defined beginning/end | Ongoing                      |
| Change-oriented       | Stability-oriented           |
| Creates something new | Maintains existing processes |

### Example

Developing a warehouse management system:

**Project:**

> Design, build, test, and deploy the system.

**Operations:**

> Run the warehouse using the system every day.

# 6. Project Constraints

The traditional project management constraint model includes:

* Scope
* Time
* Cost

Often expanded to include:

* Quality
* Risk
* Resources
* Stakeholder expectations

A useful model:

```text
             Scope
            /     \
           /       \
       Time ------- Cost
           \       /
            Quality
```

Changing one constraint often affects others.

### Example

A customer asks:

> "Can we add five more features without changing the deadline?"

The answer should not immediately be:

> "Yes."

Instead ask:

* Can scope increase?
* Do we have enough resources?
* Can quality remain unchanged?
* Does the budget increase?
* Does schedule need to change?

# 10. Business Case

A business case explains why an organization should invest in the project.

It may include:

* problem
* opportunity
* alternatives
* expected benefits
* estimated costs
* risks
* assumptions
* financial analysis
* strategic alignment

## ROI

Return on Investment:

```text
ROI = (Gain - Investment) / Investment
```

Example:

Investment = $50,000

Expected gain = $80,000

```text
ROI = (80,000 - 50,000) / 50,000
    = 0.60
    = 60%
```

Scope defines what the project includes and excludes.

Scope creep occurs when project requirements expand without appropriate control.

Later:

* mobile app
* recommendation engine
* chatbot
* payment integration
* warehouse system
* analytics dashboard

Without adjusting:

* budget
* schedule

# 18. Dependencies

Dependencies describe relationships between activities.

## Finish-to-Start

Task B starts after Task A finishes.

```text
A ─────→ B
```

## Start-to-Start

Task B starts after Task A starts.

```text
A ─────→
        B ─────→
```

## Finish-to-Finish

Task B finishes after Task A finishes.

## Start-to-Finish

Rare dependency where one task cannot finish until another starts.

# 19. Critical Path

The **Critical Path** is the longest path through the project network that determines the shortest possible project duration.

If a critical task is delayed, the project may be delayed.

Example:

```text
A → B → D → E
```

Duration:

```text
A = 3
B = 5
D = 4
E = 2

Total = 14 days
```

Another path:

```text
A → C → E
```

```text
3 + 2 + 2 = 7 days
```

Therefore the first path is critical.

# 25. Risk Management

Risk is an uncertain event that could affect project objectives.

A risk has:

```text
Probability
×
Impact
```

### Risk Score

```text
Risk Score = Probability × Impact
```

Example:

Probability = 0.4

Impact = $20,000

```text
Expected Monetary Impact = 0.4 × 20,000
                         = $8,000
```

---

## Risk Categories

### Technical Risk

Example:

> The selected technology may not scale.

### Schedule Risk

> Development may take longer than estimated.

### Financial Risk

> Costs may exceed the budget.

### Resource Risk

> A critical team member may become unavailable.

### External Risk

> Regulation or supplier changes may affect the project.

# 35. Earned Value Management

Earned Value Management (EVM) integrates scope, schedule, and cost.

Important variables:

### Planned Value

**PV**

Budgeted value of planned work.

### Earned Value

**EV**

Budgeted value of completed work.

### Actual Cost

**AC**

Actual cost of completed work.

---

## Schedule Variance

```text
SV = EV - PV
```

If:

```text
SV > 0
```

ahead of schedule.

If:

```text
SV < 0
```

behind schedule.

---

## Cost Variance

```text
CV = EV - AC
```

If:

```text
CV > 0
```

under budget.

If:

```text
CV < 0
```

over budget.

---

## Schedule Performance Index

```text
SPI = EV / PV
```

### Interpretation

```text
SPI > 1 → ahead
SPI = 1 → on schedule
SPI < 1 → behind
```

---

## Cost Performance Index

```text
CPI = EV / AC
```

### Interpretation

```text
CPI > 1 → efficient spending
CPI = 1 → exactly as planned
CPI < 1 → cost inefficiency
```

# 51. Common Project Management Mistakes

Bad:

> "Let's build an AI application."

Better:

> "Build an AI forecasting system that reduces forecast error by X%."

---

## 2. Poor Scope Definition

Undefined scope leads to scope creep.

---

## 3. Unrealistic Deadlines

A deadline is not a plan.

---

## 4. Ignoring Risks

Risks should be identified before they become issues.

---

## 5. Poor Communication

Technical success cannot compensate for organizational confusion.

---

## 6. Micromanagement

The PM should coordinate rather than control every small decision.

## 7. Ignoring Stakeholders

A technically excellent product can still fail if users reject it.

---

## 8. Measuring Activity Instead of Value

Example:

> "We completed 200 development hours."

This does not necessarily mean:

> "We created business value."

> **Project management is not simply completing tasks. It is the disciplined process of converting a desired outcome into coordinated work, managing uncertainty and constraints, and delivering measurable value.**

# Recommended Study Method

For every project, practice answering these questions:

```text
1. Why are we doing this?

2. What exactly are we delivering?

3. What is NOT included?

4. Who cares about the result?

5. Who performs the work?

6. What must happen first?

7. How long will it take?

8. How much will it cost?

9. What could go wrong?

10. How will we measure success?

11. What happens if requirements change?

12. How will we communicate progress?

13. How will we know that the project is under control?

14. How will we know that the project created value?
```

# Connection to Data Science, AI, Software & Logistics

For an AI/Data Science engineer, Project Management is especially valuable because real-world technical projects rarely fail solely because someone cannot write Python.

They often fail because of:

```text
Unclear problem
      ↓
Poor requirements
      ↓
Bad scope
      ↓
Unrealistic expectations
      ↓
Weak communication
      ↓
Poor planning
      ↓
Unmanaged risks
      ↓
Technical work without business value
```

A strong technical professional therefore needs two layers:

```text
TECHNICAL LAYER
Python
SQL
Statistics
Machine Learning
Software Engineering
Cloud
Data Engineering
        │
        ▼
PROJECT LAYER
Planning
Scope
Requirements
Risk
Cost
Schedule
Communication
Stakeholders
Value
```

For AI, data science, manufacturing, transportation, logistics, and supply-chain projects, combining both layers allows you to move from:

> **"I can build the model."**

to:

> **"I can help define the problem, plan the work, coordinate the technical solution, manage uncertainty, measure its performance, and deliver it as part of a successful project."**
