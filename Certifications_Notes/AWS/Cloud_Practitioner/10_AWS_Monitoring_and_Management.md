# Module 10: AWS Monitoring and Management

## 1. Learning Objectives

* Understand monitoring and operational management in AWS.
* Explain Amazon CloudWatch and AWS CloudTrail.
* Understand AWS Config and AWS Systems Manager.
* Identify AWS Trusted Advisor and AWS Health.
* Distinguish metrics, logs, events, and audit trails.
* Understand alarms, dashboards, automation, and resource governance.

## 2. Why Monitoring Matters

Monitoring helps organizations understand the health, performance, security, and cost of cloud workloads.

It can help teams:

* Detect application failures.
* Identify performance bottlenecks.
* Investigate unusual activity.
* Monitor resource utilization.
* Respond to operational incidents.
* Maintain visibility into cloud resources.

AWS provides multiple services for these purposes. Each service addresses different operational questions.

## 3. Amazon CloudWatch

Amazon CloudWatch monitors AWS resources and applications through metrics, logs, alarms, dashboards, and related capabilities.

### Key Components

**Metrics:** Numerical measurements collected over time.

Examples include CPU utilization, request counts, and latency.

**Logs:** Records generated by applications, operating systems, and supported services.

**Alarms:** Evaluate metrics against configured conditions and can initiate supported actions.

**Dashboards:** Visualize metrics and operational information.

**CloudWatch Logs:** Stores and provides access to log data from supported sources.

### Example

A company monitors an EC2 instance's CPU utilization. A CloudWatch alarm detects sustained high utilization and sends a notification or triggers a configured action.

### Common Use Cases

* Monitoring application health.
* Investigating performance problems.
* Creating operational dashboards.
* Alerting teams to threshold breaches.
* Monitoring supported AWS service metrics.

## 4. AWS CloudTrail

AWS CloudTrail records supported AWS account activity and API events.

It helps organizations investigate who performed an action, what action occurred, and when it happened.

### Common Use Cases

* Auditing account activity.
* Investigating unexpected resource changes.
* Supporting security investigations.
* Reviewing API activity.
* Maintaining records for governance requirements.

### Example

An EC2 instance is unexpectedly terminated. CloudTrail event records can help identify the relevant API call and the identity associated with it, when the activity was recorded and the relevant event information is available.

CloudTrail is not the same as CloudWatch. It focuses on account activity and API auditing rather than primarily monitoring operational metrics.

## 5. Amazon CloudWatch vs. AWS CloudTrail

| Feature          | Amazon CloudWatch            | AWS CloudTrail                    |
| ---------------- | ---------------------------- | --------------------------------- |
| Primary purpose  | Monitoring and observability | Account activity and API auditing |
| Typical data     | Metrics, logs, alarms        | Supported API and account events  |
| Example question | Is CPU utilization too high? | Who terminated the instance?      |
| Common use       | Performance monitoring       | Auditing and investigations       |

The services can complement each other during incident response.

## 6. AWS Config

AWS Config helps assess, audit, and evaluate supported AWS resource configurations over time.

It can record configuration changes and evaluate resources against configured rules.

### Common Use Cases

* Tracking configuration history.
* Detecting configuration drift.
* Evaluating compliance with configuration rules.
* Investigating changes to supported resources.

### Example

A company requires an S3 bucket to meet certain security configuration requirements. AWS Config can evaluate relevant supported settings using appropriate rules.

AWS Config is different from CloudTrail: Config focuses on resource configuration and configuration history, while CloudTrail focuses on recorded account activity and API events.

## 7. AWS Systems Manager

AWS Systems Manager helps manage and operate supported AWS and hybrid infrastructure.

Its capabilities include tools for:

* Operational automation.
* Parameter management.
* Patch management.
* Inventory collection.
* Remote administration.
* Runbook execution.

The exact capabilities depend on the Systems Manager feature, resource type, permissions, and configuration.

### Example

An operations team uses supported Systems Manager capabilities to automate maintenance tasks across managed instances instead of manually repeating the same steps.

Systems Manager can help reduce operational effort, but customers must configure access, automation, and change controls appropriately.

## 8. AWS Trusted Advisor

AWS Trusted Advisor provides checks and recommendations to help evaluate aspects of an AWS environment.

Its checks cover areas such as:

* Cost optimization.
* Performance.
* Security.
* Fault tolerance.
* Service quotas and operational considerations, depending on the available checks and support level.

The available checks and features vary according to AWS account and support arrangements.

### Example

Trusted Advisor may identify an opportunity to review underutilized resources or a configuration that needs attention.

Recommendations should be reviewed in context before implementation.

## 9. AWS Health

AWS Health provides information about AWS service events and issues that may affect AWS resources or accounts.

It can help customers understand relevant service disruptions, maintenance events, and account-specific health notifications.

### Example

An organization receives an AWS Health notification about an event affecting a service or resource it uses and evaluates the operational impact.

AWS Health is different from CloudWatch: CloudWatch monitors workload metrics and logs, while AWS Health reports relevant AWS service and account events.

## 10. Amazon EventBridge

Amazon EventBridge is an event bus service that routes supported events to targets according to configured rules.

It can connect operational events to automated workflows.

### Example

A supported AWS event matches an EventBridge rule and triggers a target such as a Lambda function.

EventBridge is useful when systems need to respond to events rather than relying only on periodic polling.

## 11. Monitoring and Incident Response Workflow

A basic operational workflow might look like this:

1. Collect metrics and logs using appropriate monitoring services.
2. Configure alarms for important conditions.
3. Record and review relevant API activity.
4. Investigate configuration changes.
5. Notify responsible teams.
6. Execute approved recovery or remediation procedures.
7. Review the incident and improve preventive controls.

For example, CloudWatch may identify a performance problem, CloudTrail may help establish which changes occurred, and AWS Config may show how a resource's configuration changed over time.

## 12. Exam-Focused Revision Notes

* CloudWatch monitors metrics, logs, alarms, and dashboards.
* CloudTrail records supported account and API activity.
* AWS Config tracks resource configuration changes and evaluates configurations.
* Systems Manager supports operational management and automation.
* Trusted Advisor provides recommendations and checks across supported categories.
* AWS Health reports relevant AWS service and account events.
* EventBridge routes supported events to configured targets.
* Metrics are measurements; logs are records; API audit events capture account activity.
* CloudWatch and CloudTrail have different primary purposes.
* Monitoring is most useful when alerts have clear thresholds, owners, and response procedures.
* Service features and available checks may vary by account, Region, and configuration.

## 14. Practical Exercise

A company notices that an application is slow and that an EC2 instance's configuration changed unexpectedly.

Choose services to help investigate both problems.

### Suggested Solution

* Use CloudWatch metrics and logs to investigate application performance.
* Use CloudTrail to review relevant API activity and identify recorded changes.
* Use AWS Config to examine supported resource configuration history and evaluate compliance.
* Use Systems Manager for appropriate operational investigation or remediation.
* Establish alarms and incident-response procedures to reduce the time required to detect and address future problems.
